## 实现交付

| 仓库 | 可审查的变更 |
| --- | --- |
| UniLab | 独立 G1 multisim owner 和四个评估 profile；`training/multi_source.py` 装配与语义校验；CLI/训练入口；严格 checkpoint/Sim2Sim 评估与报告聚合；`training/validation.py` 验收编排和资源记录；测试、ADR、说明 |
| unilab_rl | `ipc/multi_source_env.py`、共享内存、worker 和资源清理模块；可 pickle 工厂注入；固定 slice、双缓冲、并发提交/同步屏障；失败封锁与嵌套 SHM 回收；`algos/rsl_rl_validation.py` 完整更新边界停止；CPU/故障/PPO 测试与文档 |
| unisim | Isaac 共享协议 v2 能力握手和 DR 槽；选中行 mass/KP/KD 原生写入及 nominal 缓存；初始化映射；真实 IsaacSim ContactSensor；协议/SDK doubles/native 读回测试与文档 |

生产实验保持四源各 2000、总计 8000、rollout 24、每源 25%；没有缩容、
删源、关闭 DR/接触奖励或将联合训练改为顺序采样。`multisim` 不是物理
SimBackend。一个现有 PPO runner 直接消费组合环境，没有复制训练循环。

## 真实 Motrix 部分证据

只运行 native CPU Motrix，四环境；没有使用替代机器人或 fake backend。
在各仓库工作目录，以同一个 CPU editable 环境执行：

```bash
export UV_PROJECT_ENVIRONMENT=/home/wsm/wang-sm/UniLab/.venv-cpu UV_NO_SYNC=1
export CUDA_VISIBLE_DEVICES='' PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 UNILAB_RUN_MULTISIM_PHYSICS=1

uv run --no-sync pytest tests/backends/test_g1_multisim_physics.py -q -k motrix -m ''

cd ../unisim
UNILAB_G1_SCENE=/home/wsm/wang-sm/UniLab/src/unilab/assets/robots/g1/scene_flat.xml \
  uv run --no-sync pytest tests/test_multisim_native_readback.py -q -k motrix -m ''
```

- 效果用例：**1 passed、3 deselected，零 skip**。pelvis mass、全部 29 个关节
  KP/KD、组合 DR 的物理效果，选中行隔离、重复 nominal 恢复和落地/离地接触
  检查通过；重复 nominal 轨迹差为零。
- native 读回：**1 failed、1 deselected，零 skip**。首次选中行 mass/KP/KD
  读回匹配，随后在 required inertia assertion 失败。当前绑定没有 live
  per-environment inertia；model-only 表不能证明实际 solver 惯量保持不变。
- 这不是发现了惯量发生变化，而是尚未验证。没有放宽断言、用 nominal 表
  冒充 live 值，或把通过的效果检查当作完整 G1 成功。

完整日志和 JUnit：`val/g1-multisim-20260912/motrix-physics/`。
